## 一、设计概述

ZServer 不是一个使用 EF Core 或 Code-First 方式创建数据库的应用程序。项目定位为**地图瓦片服务器**，设计核心是**连接到已有的 PostgreSQL/PostGIS 空间数据库**，读取空间数据进行动态渲染。因此，ZServer 本身不管理数据库 Schema 的创建和迁移，而是通过 JSON 配置文件来映射和访问数据库中的表结构。

### 设计理念

```
用户已有空间数据库 ──▶ ZServer 配置文件 ──▶ 运行时渲染
(PostGIS 中的表)        (映射表名、字段)      (读取数据生成瓦片)
```

ZServer 只需知道以下信息即可访问空间数据：
- 数据库连接字符串
- 表名（`sourceTable`）
- 几何字段名（`sourceGeometry`）
- 空间参考编号（`sourceSRID`）

## 二、核心设计思路

### 2.1 空间数据读取模式

ZServer 通过 Npgsql 驱动直连 PostgreSQL，利用 PostGIS 的空间函数进行查询。每个地图图层对应数据库中的一张空间表（或视图）。

```
┌─────────┐      SQL 查询（Npgsql）     ┌──────────────┐
│ ZServer │ ──────────────────────────▶ │ PostGIS      │
│          │  SELECT geom, attr1, attr2 │ 空间数据库    │
│          │  FROM polygon              │              │
│          │  WHERE ST_Intersects(      │ polygon 表   │
│          │    geom, @extent)          │              │
│          │ ◀───────────────────────── │              │
│          │    Feature 集合             │              │
└─────────┘                            └──────────────┘
```

### 2.2 配置方式

无需编写任何数据库迁移代码。在 `conf/zserver.json` 中配置即可：

```json
{
  "sources": {
    "my_source": {
      "provider": "ZMap.Source.Postgre.PostgreSource, ZMap.Source.Postgre",
      "connectionString": "User ID=postgres;Password=xxx;Host=localhost;Port=5432;Database=zserver_dev;Pooling=true;"
    }
  },
  "layers": {
    "my_layer": {
      "resourceGroup": "default",
      "source": "my_source",
      "sourceTable": "polygon",
      "sourceGeometry": "geom",
      "sourceSRID": 4326,
      "styleGroups": ["my_style"]
    }
  }
}
```

## 三、空间数据表结构建议

建议用户在 PostgreSQL/PostGIS 中创建的空间数据表遵循以下结构：

### 3.1 矢量数据表结构

```sql
-- 示例：多边形图层表
CREATE TABLE polygon (
    id SERIAL PRIMARY KEY,                          -- 主键
    name VARCHAR(255),                              -- 名称（可选）
    type VARCHAR(50),                               -- 分类（可选）
    code VARCHAR(50),                               -- 编码（可选）
    geom GEOMETRY(GEOMETRY, 4326),                  -- 几何字段（必须）
    created_at TIMESTAMP DEFAULT NOW(),             -- 创建时间（可选）
    updated_at TIMESTAMP DEFAULT NOW()              -- 更新时间（可选）
);

-- 创建空间索引（必须）
CREATE INDEX idx_polygon_geom ON polygon USING GIST (geom);

-- 可选：常用属性字段索引
CREATE INDEX idx_polygon_name ON polygon (name);
CREATE INDEX idx_polygon_type ON polygon (type);
```

### 3.2 推荐字段说明

| 字段 | 类型 | 必须 | 说明 |
|------|------|------|------|
| `id` | SERIAL / UUID | 推荐 | 主键 |
| `geom` | GEOMETRY | **必须** | 几何字段，支持 Point/LineString/Polygon/Multi* 等 |
| `name` | VARCHAR | 可选 | 用于显示标签的字段 |
| 其他属性字段 | 按需 | 可选 | 可在样式中引用 |

### 3.3 多图层表设计示例

```sql
-- 道路图层
CREATE TABLE roads (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255),
    road_type VARCHAR(50),
    width NUMERIC(10,2),
    geom GEOMETRY(MULTILINESTRING, 4326)
);
CREATE INDEX idx_roads_geom ON roads USING GIST (geom);

-- 建筑图层
CREATE TABLE buildings (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255),
    floors INTEGER,
    height NUMERIC(10,2),
    geom GEOMETRY(MULTIPOLYGON, 4326)
);
CREATE INDEX idx_buildings_geom ON buildings USING GIST (geom);
```

## 四、配置存储

ZServer 的所有配置（图层、数据源、样式、瓦片网格等）存储在 **JSON 文件**中，而非数据库中。

### 4.1 配置文件清单

| 文件 | 路径 | 说明 |
|------|------|------|
| appsettings.json | `conf/appsettings.json` | 应用配置（Orleans、认证等） |
| zserver.json | `conf/zserver.json` | 服务配置（图层、数据源、样式等） |
| serilog.json | `conf/serilog.json` | Serilog 日志配置 |

### 4.2 配置提供者模式

支持两种配置提供者：

| 提供者 | 说明 | 适用场景 |
|--------|------|----------|
| `file` | 从本地 JSON 文件读取（默认） | 单机部署、开发环境 |
| `socodb` | 从远程 API 获取配置 | 配置中心化管理 |

## 五、索引建议

### 5.1 空间索引

PostGIS 空间查询是 ZServer 渲染性能的关键。

```sql
-- 必须为每个图层的几何字段创建 GIST 索引
CREATE INDEX [index_name] ON [table_name] USING GIST ([geometry_column]);

-- 示例
CREATE INDEX idx_polygon_geom ON polygon USING GIST (geom);
```

### 5.2 空间索引选择

| 索引类型 | 适用操作 | 建议 |
|----------|----------|------|
| GIST | ST_Intersects, ST_Within, ST_DWithin | **必须**，空间查询的核心索引 |
| BRIN | 按空间顺序扫描 | 仅适用于超大表（百万级）时作为补充 |

### 5.3 属性索引

对于常用的过滤字段（如 `name`、`type`、`code`），建议创建 B-tree 索引：

```sql
CREATE INDEX idx_polygon_name ON polygon (name);
CREATE INDEX idx_polygon_type ON polygon (type);
```

### 5.4 复合索引

当 `Z_FILTER` 对某字段频繁过滤时，可考虑复合索引：

```sql
-- 如果经常根据 type 过滤并对 geom 做空间查询
-- PostgreSQL 支持部分索引（Partial Index）
CREATE INDEX idx_polygon_type_geom ON polygon (type) WHERE type = '特定类型';
```

## 六、Orleans 集群表结构

当 ZServer 运行在**集群模式**（standalone=false）时，Orleans 使用 ADO.NET（PostgreSQL）管理集群成员和 Reminder 服务。

### 6.1 OrleansMembership 表

Orleans 自动创建以下表用于集群协调：

| 表名 | 用途 |
|------|------|
| `OrleansMembership` | Silo 成员注册与心跳检测 |
| `OrleansMembershipVersion` | 集群版本控制 |
| `OrleansReminders` | Reminder 服务持久化 |

### 6.2 Orleans 表结构示例

```sql
-- OrleansMembershipTable（示例）
CREATE TABLE orleansmembership
(
    deploymentid VARCHAR(150) NOT NULL,
    address VARCHAR(45) NOT NULL,
    port INTEGER NOT NULL,
    generation INTEGER NOT NULL,
    siloname VARCHAR(150) NOT NULL,
    hostname VARCHAR(150) NOT NULL,
    status INTEGER NOT NULL,
    proxystatus INTEGER NOT NULL,
    susspecttimes TIMESTAMP NOT NULL,
    starttime TIMESTAMP NOT NULL,
    iamalivetimetimestamp TIMESTAMP NOT NULL,
    PRIMARY KEY (deploymentid, address, port, generation)
);
```

### 6.3 集群配置


## 七、非功能数据库需求

### 7.1 连接管理

- 使用 Npgsql 连接池（`Pooling=true`）
- 连接字符串通过环境变量 `ZSERVER_` 前缀可覆盖

### 7.2 性能建议

| 场景 | 建议 |
|------|------|
| 坐标系 | 统一使用 EPSG:4326 存储 |
| 查询优化 | 确保空间索引存在 |
| 数据量 | 单表控制在千万级以内 |
| 连接数 | 根据并发量调整连接池大小（MaxPoolSize） |

### 7.3 备份建议

ZServer 不管理数据库备份，建议使用 PostgreSQL 原生备份工具：
- `pg_dump`：逻辑备份
- `pg_basebackup`：物理备份
- WAL 归档：持续归档（用于 PITR）
