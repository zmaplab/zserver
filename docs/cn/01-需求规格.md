## 一、功能概述

ZServer 是一个基于 **Microsoft Orleans Actor 模型** 实现的分布式计算地图瓦片服务器，完全符合 **OpenGIS Web 服务器规范**，提供 OGC WMS（Web Map Service）和 WMTS（Web Map Tile Service）标准服务。项目采用 .NET 10 与 ASP.NET Core 技术栈，利用 SkiaSharp 进行跨平台地图渲染，支持水平扩展的集群化部署。

ZServer 的核心定位是为 GIS 政务/企业应用、位置服务（LBS）平台以及分布式 GIS 平台提供高并发、高可用的地图发布服务。通过 Orleans 的 Actor 模型，每个地图瓦片映射为一个 Actor，实现无锁并发更新和水平伸缩。

系统支持多种数据源接入（PostgreSQL/PostGIS、ShapeFile、COG GeoTIFF、GDAL、远程 WMTS），并通过 JSON 配置文件灵活管理图层、样式和数据源的组合。安全性方面支持 JWT Bearer Token 认证和 Simple Token 认证，配合基于 Scope 的授权策略。

## 二、功能需求清单

### 2.1 WMS 服务

| 功能 | 描述 | 优先级 |
|------|------|--------|
| GetCapabilities | 返回 WMS 服务的元数据信息（图层、样式、坐标系、支持的操作等） | 高 |
| GetMap | 根据请求参数动态渲染并返回地图图像（PNG/JPEG），支持多图层叠加 | 高 |
| GetFeatureInfo | 根据像素坐标查询地图要素属性信息，以 GeoJSON FeatureCollection 格式返回 | 高 |

**WMS GetMap 参数支持**：
- 图层选择（`layers`）：支持逗号分隔的多图层、resourceGroup:layer 格式
- 样式选择（`styles`）：与 layers 一一对应的样式列表
- 空间参考（`srs`）：EPSG:4326、EPSG:3857、EPSG:900913 等
- 地理范围（`bbox`）：minx,miny,maxx,maxy 格式
- 输出尺寸（width/height）、输出格式（format）、透明背景（transparent）、背景色（bgColor）
- 自定义过滤器（`Z_FILTER`）：SQL WHERE 条件表达式
- 格式化参数（`FORMAT_OPTIONS`）：dpi 设置等
- 缓冲设置（buffer）和边框设置（bordered）

### 2.2 WMTS 服务

| 功能 | 描述 | 优先级 |
|------|------|--------|
| GetTile | 根据瓦片矩阵、行列号返回预定义网格的地图瓦片图像 | 高 |
| 瓦片缓存 | 基于文件系统的瓦片缓存机制，避免重复渲染 | 高 |
| 多图层合并 | 支持多个图层合并在同一个瓦片中渲染 | 中 |

**WMTS GetTile 参数支持**：
- 图层（`layer`）、样式（`style`）
- 瓦片矩阵（`tileMatrix`）、行号（`tileRow`）、列号（`tileCol`）
- 瓦片矩阵集（`tileMatrixSet`）：EPSG:4326、EPSG:3857 等
- 输出格式（`format`）：默认 image/png
- 过滤器（`Z_FILTER`）和边框设置（bordered）

## 三、业务规则需求

### 3.1 图层渲染规则

1. **图层叠加顺序**：WMS 请求中 layers 参数最左边的图层在底层，依次向上叠加。渲染时按倒序遍历图层，以保证上层图层覆盖下层。
2. **缩放可见性**：图层和样式组均可设置 `minZoom`/`maxZoom`，超出范围的图层不参与渲染。缩放单位（`zoomUnit`）支持 Scale（比例尺）和 Zoom（缩放级别）两种模式。
3. **坐标系转换**：前端的请求 SRID 与数据源的 SRID 不一致时，自动进行坐标系转换（使用 ProjNET），转换后做范围相交判断。
4. **范围交集**：只有当瓦片/视窗范围与图层的显示范围（Envelope）相交时，才执行渲染流程。
5. **过滤器合并**：WMTS 支持的 zFilter 可对多图层使用分号分隔的多过滤器，过滤器数量必须与图层数量一致。

### 3.2 瓦片缓存规则

1. **缓存文件路径**：缓存文件按 `cache/wmts/{layerKey}/{tileMatrixSet}/{tileMatrix}/{tileRow}/{tileCol}.png` 层次结构存储。
2. **过滤器缓存**：若请求包含 Z_FILTER，会在文件名中追加过滤器哈希值，避免不同过滤器的瓦片相互覆盖。
3. **边框缓存**：带边框的瓦片和不带边框的瓦片使用不同的缓存键。
4. **缓存跳过**：在 Debug 模式下跳过缓存，直接渲染。
5. **目录自动创建**：瓦片文件写入前自动创建目录结构。

### 3.3 权限规则

1. **API 层认证**：所有 API 端点默认受 `Authorize(Policy = "default")` 保护。
2. **Scope 策略**：默认策略要求 Token 包含 `scope` 声明且值为 `apiName`（默认 zserver-api）。
3. **文档策略**：单独的 `api-document` 策略要求 `role` 为 `zserver-api-document`。
4. **图层级权限**：可选的 `IPermissionService` 支持按 resourceId 进行细粒度读权限控制。
5. **认证开关**：`EnableAuthorization=false` 时跳过所有认证检查（开发模式）。

### 3.4 动态编译规则

1. **CQL 过滤器**：图层支持 Z_FILTER 参数，可编写 SQL WHERE 条件进行要素过滤。
2. **运行时编译**：使用 Natasha 库在运行时将 C# 表达式字符串编译为可执行代码，用于条件判断。
3. **表达式缓存**：编译后的表达式结果会被缓存，避免重复编译开销。

### 3.5 数据源规则

1. **空间数据库**：PostGIS 数据源通过配置的表名（`sourceTable`）和几何字段（`sourceGeometry`）进行空间查询。
2. **自动范围**：若用户未指定图层显示范围（Envelope），自动使用数据源的范围。
3. **坐标系一致**：图层的坐标系和数据源的坐标系必须一致，配置错误的 SRID 可能导致渲染异常。

## 四、非功能需求

### 4.1 性能需求

| 指标 | 要求 | 说明 |
|------|------|------|
| 瓦片响应时间 | < 500ms（缓存命中 < 10ms） | 首次渲染含数据库查询和图片合成时间 |
| 并发支持 | 支持高并发瓦片请求 | 依赖 Orleans Actor 模型的无锁并发 |
| 图片渲染 | 支持 256×256、512×512 瓦片尺寸 | 可通过 GridSet 配置 |
| 最大请求体 | 500MB | Kestrel 配置上限 |

### 4.2 扩展性需求

| 指标 | 要求 | 说明 |
|------|------|------|
| 水平扩展 | 支持添加更多 Silo 节点 | 通过 Orleans ADO.NET 集群管理 |
| 无状态设计 | 瓦片 Actor 无状态 | 不保留持久状态，按需渲染 |
| 负载均衡 | WMS IntegerKey Grain 自动负载均衡 | StatelessWorker 模式 |
| 数据源扩展 | 插件化数据源 | 实现 IVectorSource/IRasterSource 即可 |
| 渲染器扩展 | 插件化渲染器 | 实现 IRenderer/IStyleVisitor 即可 |

### 4.3 可用性需求

| 指标 | 要求 | 说明 |
|------|------|------|
| 单点故障 | 集群模式下无单点故障 | Orleans 自动故障转移 |
| 健康检查 | `/healthz` 端点 | 支持 Kubernetes 等容器编排 |
| 日志 | Serilog 控制台 + 滚动文件日志 | 支持敏感数据日志开关 |
| 集群监控 | Orleans Dashboard | 实时查看 Silo 状态、激活数、请求数 |

### 4.4 安全需求

| 指标 | 要求 | 说明 |
|------|------|------|
| 认证 | JWT Bearer Token / Simple Token | 支持自定义颁发者和密钥 |
| 授权 | Scope 声明 / Role 声明 | 细粒度 API 权限控制 |
| CORS | 可配置的跨域策略 | 生产环境建议限制来源 |
| 敏感信息 | 日志中可屏蔽敏感参数 | EnableSensitiveDataLogging 开关 |

### 4.5 兼容性需求

| 指标 | 要求 | 说明 |
|------|------|------|
| WMS 标准 | 兼容 OGC WMS 1.1.1 / 1.3.0 | 支持 GetMap、GetFeatureInfo |
| WMTS 标准 | 兼容 OGC WMTS 1.0.0 | 支持 GetTile |
| 坐标系 | EPSG:4326、EPSG:3857（900913） | 通过 ProjNET 扩展更多坐标系 |
| 图像格式 | PNG、JPEG、WebP、GIF、BMP | 通过 SkiaSharp 支持 |

### 4.6 部署环境需求

| 环境 | 要求 |
|------|------|
| 运行时 | .NET 10.0 SDK / Runtime |
| 数据库 | PostgreSQL 13+ with PostGIS |
| 容器化 | Docker / Docker Compose |
| 集群 | 支持 Windows / Linux 混合环境 |
| 前端 | Node.js 16+（如需要 Leaflet 前端） |
