## 一、环境要求

### 1.1 软件依赖

| 组件 | 版本要求 | 说明 |
|------|----------|------|
| .NET SDK/Runtime | 10.0 | 编译和运行环境 |
| PostgreSQL | 13+ | 空间数据库（需安装 PostGIS 扩展） |
| PostGIS | 3.0+ | 空间数据扩展 |
| Docker | 最新版 | 可选，用于容器化部署 |
| Node.js | 16+ | 可选，用于前端开发 |
| GDAL | 可选 | 用于 GDAL 数据源 |
| ProjNET | 内置依赖 | 坐标变换库 |

### 1.2 硬件建议

| 部署规模 | CPU | 内存 | 磁盘 |
|----------|-----|------|------|
| 开发/测试 | 2 核 | 4 GB | 20 GB |
| 小规模生产 | 4 核 | 8 GB | 100 GB（含缓存） |
| 中规模集群 | 8 核 × N 节点 | 16 GB × N | 500 GB × N |

## 二、配置文件说明

### 2.1 配置文件清单

| 文件 | 路径 | 说明 |
|------|------|------|
| `appsettings.json` | `conf/appsettings.json` | 应用主配置 |
| `zserver.json` | `conf/zserver.json` | 服务配置（图层、数据源、样式） |
| `serilog.json` | `conf/serilog.json` | Serilog 日志配置 |

### 2.2 appsettings.json 配置项

```json
{
  "standalone": true,
  "jwtBearer": {
    "validateAudience": false,
    "validateIssuer": false,
    "KeyPath": ""
  },
  "tokens": ["682be39c9d8786225072af8b"],
  "apiName": "zserver-api",
  "permissionApi": "",
  "config": {
    "provider": "file",
    "address": "conf/zserver.json"
  },
  "orleans": {
    "connectionString": "User ID=postgres;Password=;Host=localhost;Port=5432;Database=zserver_dev;Pooling=true;",
    "invariant": "Npgsql",
    "siloName": "zserver",
    "clusterId": "zserver",
    "serviceId": "zserver",
    "gatewayPort": 41113,
    "siloPort": 31113,
    "dashboard": true
  }
}
```

**配置项详解**：

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `standalone` | bool | `true` | 单机模式（true）或集群模式（false） |
| `EnableAuthorization` | string | - | 是否启用认证（设为 `false` 跳过认证） |
| `jwtBearer.authority` | string | `""` | JWT 颁发者地址 |
| `jwtBearer.keyPath` | string | `""` | JWT 公钥路径 |
| `tokens` | string[] | `[]` | Simple Token 白名单 |
| `apiName` | string | `"zserver-api"` | API 名称（用于 scope 校验） |
| `config.provider` | string | `"file"` | 配置提供者：`file` 或 `socodb` |
| `config.address` | string | `""` | 配置文件路径 |
| `orleans.connectionString` | string | `""` | Orleans 集群数据库连接 |
| `orleans.invariant` | string | `"Npgsql"` | 数据库驱动 |
| `orleans.siloName` | string | `"zserver"` | Silo 名称 |
| `orleans.clusterId` | string | `"zserver"` | 集群 ID |
| `orleans.serviceId` | string | `"zserver"` | 服务 ID |
| `orleans.gatewayPort` | int | `41113` | 网关端口 |
| `orleans.siloPort` | int | `31113` | Silo 内部通信端口 |
| `orleans.dashboard` | bool | `true` | 是否启用 Orleans Dashboard |

## 三、环境变量

ZServer 支持通过环境变量覆盖配置，环境变量前缀为 `ZSERVER_`。

### 3.1 核心环境变量

| 变量名 | 对应配置项 | 说明 |
|--------|-----------|------|
| `ZSERVER_PORT` | - | HTTP 服务端口 |
| `ZSERVER_HostIP` / `HOST_IP` | - | Orleans 主机 IP |
| `ZSERVER_Standalone` | `standalone` | 单机/集群模式 |
| `ZSERVER_ClusterSiloPort` | `orleans.siloPort` | Silo 端口 |
| `ZSERVER_ClusterGatewayPort` | `orleans.gatewayPort` | 网关端口 |
| `ZSERVER_ClusterDashboard` | `orleans.dashboard` | Dashboard 开关 |
| `ZSERVER_ClusterDashboardPort` | - | Dashboard 端口 |
| `ZSERVER_EnableAuthorization` | `EnableAuthorization` | 认证开关 |
| `ZSERVER_EnableSensitiveDataLogging` | - | 敏感数据日志开关 |
| `ZSERVER_LOG_PATH` / `LOG_PATH` | - | 日志文件路径 |
| `ZSERVER_ClusterConnectionString` | `orleans.connectionString` | 集群数据库连接 |
| `TZ` | - | 时区（如 `Asia/Shanghai`） |

### 3.2 示例

```bash
# 单机模式
export ZSERVER_Port=8200
export ZSERVER_Standalone=true
export ZSERVER_EnableAuthorization=false

# 集群模式
export ZSERVER_Port=8100
export ZSERVER_Standalone=false
export ZSERVER_ClusterSiloPort=10001
export ZSERVER_ClusterGatewayPort=20001
export ZSERVER_HostIP=192.168.1.100
export ZSERVER_ClusterConnectionString="User ID=postgres;Password=xxx;Host=192.168.1.1;Port=5432;Database=zserver_cluster;"
```

## 四、部署步骤

### 4.1 快速启动（单机模式）

```bash
# 1. 启动 PostgreSQL（Docker）
docker run --name postgis -p 5432:5432 -e POSTGRES_PASSWORD=1qazZAQ! -d postgis/postgis

# 2. 创建数据库和 PostGIS 扩展
docker exec -it postgis psql -U postgres -c "CREATE DATABASE zserver_dev;"
docker exec -it postgis psql -U postgres -d zserver_dev -c "CREATE EXTENSION postgis;"

# 3. 配置 conf/appsettings.json（standalone=true）

# 4. 编译运行（单机模式）
dotnet run --project src/ZServer.API -- --Standalone true --Port 8200 --ClusterDashboard true --ClusterDashboardPort 8182

# 5. 访问
# API: http://localhost:8200
# Dashboard: http://localhost:8182/dashboard
```

### 4.2 Docker 部署

#### Docker Compose

```yaml
version: "3"
services:
  postgis:
    image: postgis/postgis
    restart: always
    environment:
      POSTGRES_PASSWORD: 1qazZAQ!
    volumes:
      - postgis-data:/var/lib/postgresql/data
    ports:
      - 5432:5432

  zserver:
    image: zlzforever/zserver-api:latest
    restart: always
    ports:
      - 8200:8200
      - 8182:8182
      - 41113:41113
      - 31113:31113
    volumes:
      - ./conf:/app/conf
      - ./cache:/app/cache
      - ./symbols:/app/Symbols
      - ./fonts:/app/fonts
      - ./shapes:/app/shapes
      - ./sld:/app/sld
    environment:
      - PORT=8200
      - standalone=false
      - ClusterDashboard=true
      - ClusterDashboardPort=8182
      - HOST_IP=192.168.0.244
      - TZ=Asia/Shanghai

volumes:
  postgis-data:
```

```bash
# 启动
docker-compose up -d

# 查看日志
docker-compose logs -f
```

#### Docker 镜像构建

```bash
# 使用内置 Dockerfile 构建
docker build -f API.Dockerfile -t zserver-api:latest .

# ARM 架构镜像
docker build -f API_ARM.Dockerfile -t zserver-api:arm64 .
```

### 4.3 集群模式部署

#### 架构概览

```text
                     ┌──────────────┐
                     │  HTTP 请求    │
                     └──────┬───────┘
                            │
              ┌─────────────┴─────────────┐
              │   Nginx / 负载均衡器      │
              │   (可选，轮询策略)         │
              └─────────────┬─────────────┘
                            │
         ┌──────────────────┼──────────────────┐
         ▼                  ▼                  ▼
   ┌───────────┐      ┌───────────┐      ┌───────────┐
   │ Silo+API  │      │ Silo+API  │      │ Silo+API  │
   │ 节点 1    │◀────▶│ 节点 2    │◀────▶│ 节点 3    │
   └─────┬─────┘      └─────┬─────┘      └─────┬─────┘
         │                   │                   │
         └───────────────────┼───────────────────┘
                             │
                     ┌───────┴───────┐
                     │  PostgreSQL   │
                     │ (Orleans集群  │
                     │  数据库)      │
                     └───────────────┘
```

#### 集群部署步骤

```bash
# 1. 准备 PostgreSQL（需安装 PostGIS）
# 创建 Orleans 集群数据库
CREATE DATABASE zserver_cluster;
CREATE EXTENSION postgis;

# 2. 配置 conf/appsettings.json（standalone=false）
{
  "standalone": false,
  "orleans": {
    "connectionString": "User ID=postgres;Password=xxx;Host=192.168.1.1;Port=5432;Database=zserver_cluster;Pooling=true;",
    "invariant": "Npgsql",
    "siloName": "zserver-node-1",
    "clusterId": "zserver",
    "serviceId": "zserver",
    "gatewayPort": 41113,
    "siloPort": 31113,
    "dashboard": true
  }
}

# 3. 启动节点 1
dotnet run --project src/ZServer.API -- \
  --Standalone false \
  --ClusterSiloPort 10001 \
  --ClusterGatewayPort 20001 \
  --Port 8100

# 4. 启动节点 2（相同配置，不同端口）
dotnet run --project src/ZServer.API -- \
  --Standalone false \
  --ClusterSiloPort 10002 \
  --ClusterGatewayPort 20002 \
  --Port 8200

# 5. 可选：启动独立 Silo 宿主（仅运行 Grain，不处理 HTTP）
dotnet run --project src/ZServer.SiloHost
```

#### 集群高可用效果

- **Silo 宕机**：Orleans 自动检测，分配到其他 Silo 的请求自动路由
- **滚动更新**：可逐个重启节点而不影响服务
- **水平扩展**：增加节点后自动加入集群，分担负载

### 4.4 独立 Silo 宿主

```bash
# 启动独立 Silo 节点（不包含 API）
dotnet run --project src/ZServer.SiloHost
```

在生产环境中，可将 Silo 和 API 分离部署：
- **API 节点**：运行 ZServer.API（Silo + Client co-host）
- **Silo 节点**：运行 ZServer.SiloHost（纯 Silo，不处理 HTTP）

## 五、数据准备

### 5.1 创建空间数据库

```sql
-- 创建数据库
CREATE DATABASE zserver_dev;

-- 连接到数据库
\c zserver_dev;

-- 安装 PostGIS 扩展
CREATE EXTENSION postgis;
CREATE EXTENSION postgis_raster;  -- 可选，如需栅格支持

-- 验证安装
SELECT PostGIS_Version();
```

### 5.2 导入数据（推荐方式）

```bash
# 通过 QGIS 导入 SHP 文件
# 打开 QGIS → 拖入 SHP 文件 → 右键导出到 PostgreSQL

# 通过 shp2pgsql 命令行导入
shp2pgsql -s 4326 -I /path/to/shapefile.shp polygon | psql -U postgres -d zserver_dev

# 验证数据
psql -U postgres -d zserver_dev -c "SELECT ST_AsGeoJSON(geom) FROM polygon LIMIT 1;"
```

### 5.3 数据验证

```sql
-- 检查空间索引是否存在
SELECT tablename, indexname, indexdef
FROM pg_indexes
WHERE tablename IN ('polygon', 'roads', 'buildings');

-- 检查数据量
SELECT COUNT(*) FROM polygon;

-- 检查范围
SELECT ST_AsText(ST_Extent(geom)) FROM polygon;
```

## 七、操作指南

### 7.1 启动与停止

```bash
# 启动（单机模式）
dotnet run --project src/ZServer.API --Standalone true --Port 8200

# 启动（集群模式）
dotnet run --project src/ZServer.API --Standalone false --ClusterSiloPort 10001 --ClusterGatewayPort 20001 --Port 8100

# 后台运行（Docker）
docker-compose up -d

# 停止（Docker）
docker-compose down
```

### 7.2 添加图层配置

编辑 `conf/zserver.json`，按以下步骤配置新图层：

1. 在 `sources` 中添加数据源
2. 在 `styleGroups` 中添加样式组
3. 在 `layers` 中添加图层，引用上述数据源和样式组
4. 重启服务或等待自动刷新

> **配置刷新**：部分 Store 支持运行时刷新，可通过触发 `RefreshConfigService` 更新配置，无需重启。

### 7.3 认证配置

#### 启用 JWT 认证

```json
{
  "EnableAuthorization": true,
  "jwtBearer": {
    "authority": "https://auth.example.com",
    "requireHttpsMetadata": false,
    "validateAudience": true,
    "validateIssuer": true,
    "keyPath": "/path/to/public-key.pem"
  },
  "apiName": "zserver-api",
  "tokens": []
}
```

#### 使用 Simple Token

```json
{
  "EnableAuthorization": true,
  "jwtBearer": {
    "validateAudience": false,
    "validateIssuer": false
  },
  "tokens": ["your-token-here"],
  "apiName": "zserver-api"
}
```

请求时在 HTTP Header 中添加：
```
Authorization: Bearer your-token-here
```

#### 关闭认证（开发环境）

```json
{
  "EnableAuthorization": false
}
```

### 7.4 CORS 配置

ZServer 默认允许所有来源（开发环境），生产环境建议限制：

```csharp
// Program.cs
services.AddCors(option =>
{
    option.AddPolicy(CrosPolicy, policy =>
        policy.WithOrigins("https://your-frontend.com")
            .AllowAnyMethod()
            .AllowAnyHeader()
            .AllowCredentials()
    );
});
```

### 7.5 Orleans Dashboard 监控

启动后访问 `http://localhost:8182/dashboard`（端口可在配置中修改）。

Dashboard 提供：
- **Silos**：集群中所有 Silo 节点列表
- **Grains**：各类型 Grain 的激活数量
- **Requests**：请求处理速率
- **Activation Count**：Grain 激活数变化趋势

## 八、常见问题 FAQ

### Q1: 启动失败，提示数据库连接错误？

检查以下配置：
1. PostgreSQL 是否已启动
2. 连接字符串中的 `Host`、`Port`、`Username`、`Password` 是否正确
3. 数据库是否存在（集群模式需要 `zserver_cluster` 数据库）
4. PostGIS 扩展是否已安装
5. 网络防火墙是否阻止了连接

### Q2: WMS 请求返回空图像？

可能原因：
1. 图层名称不正确（检查 zserver.json 中的配置）
2. bbox 范围不在数据范围内
3. SRS 与数据源 SRID 不匹配
4. 图层未启用（`enabled: false`）
5. 当前缩放级别不在图层的可见范围内
6. 数据源连接失败（检查日志）

### Q3: WMTS 瓦片不显示？

可能原因：
1. tileMatrixSet 与图层 SRS 不匹配
2. tileRow/tileCol 超出有效范围
3. 瓦片计算错误（GridSet 配置不正确）
4. 权限不足

### Q4: 如何过滤特定要素？

在请求中使用 `Z_FILTER` 参数：

```http
# 过滤名称等于"测试地块"的要素
/wms?request=GetMap&layers=polygon&Z_FILTER=name='测试地块'&...
```

### Q5: 如何配置多图层叠加？

在请求的 `layers` 参数中用逗号分隔：
```
layers=道路,建筑物,绿地
```

或使用资源组格式：
```
layers=group1:道路,group2:建筑物
```

### Q6: 如何调整瓦片缓存位置？

缓存默认存储在 `{BaseDirectory}/cache/` 目录。可通过 Docker 挂载或符号链接调整路径：

```bash
ln -s /mnt/large-disk/cache /app/cache
```

### Q7: 如何启用 HTTPS？

建议使用反向代理（如 Nginx）终止 HTTPS：
```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;
    
    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;
    
    location / {
        proxy_pass http://localhost:8200;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

### Q8: 日志文件在哪里？

日志默认输出到控制台和滚动文件。文件日志路径：
- 默认：`{BaseDirectory}/logs/log.txt`
- 可通过 `LOG_PATH` 或 `ZSERVER_LOG_PATH` 环境变量修改

### Q9: 如何调整瓦片尺寸？

在 GridSet 配置中设置 `TileWidth` 和 `TileHeight`（默认 256×256）。

### Q10: 集群节点数量建议？

- 小规模：2~3 个节点
- 中规模：4~8 个节点
- 大规模：8 个节点以上（建议配合负载均衡器）
