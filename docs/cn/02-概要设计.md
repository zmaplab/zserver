## 一、系统架构

ZServer 采用四层分层架构，基于 Orleans Actor 模型实现分布式计算。整体自上而下分为：HTTP 接入层、Grain 服务层、核心引擎层和数据源层。

```
┌─────────────────────────────────────────────────────────────────────┐
│                        HTTP 接入层 (ZServer.API)                     │
│              ASP.NET Core Web API + Kestrel + Middleware            │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌─────────┐ │
│  │ WMSController │  │WMTSController│  │XyzController │  │ToolCtrl │ │
│  └──────────────┘  └──────────────┘  └──────────────┘  └─────────┘ │
├─────────────────────────────────────────────────────────────────────┤
│                      Orleans Actor 层 (Grains)                      │
│  ┌─────────────────┐  ┌─────────────────┐  ┌──────────────────────┐ │
│  │    WMSGrain      │  │   WMTSGrain     │  │    XyzGrain         │ │
│  │  (IntegerKey)    │  │  (StringKey)     │  │  (StringKey)        │ │
│  │ [StatelessWorker]│  │                  │  │  (未实现)           │ │

│  └──────────────────────────────────────────────────────────────┘    │
├─────────────────────────────────────────────────────────────────────┤
│                        核心引擎层 (ZMap)                              │
│  ┌───────────┐ ┌──────────┐ ┌───────────┐ ┌────────────────────┐   │
│  │  Map/Layer │ │ OGC WMS │ │ OGC WMTS  │ │  Style/StyleGroup  │   │
```

### 架构层次说明

| 层级 | 技术选型 | 主要职责 |
|------|----------|----------|
| HTTP 接入层 | ASP.NET Core 10, Kestrel | 接收 HTTP 请求，参数验证，认证授权，响应输出 |
| Actor 层 | Microsoft Orleans 10 | 分布式计算单元，处理 WMS/WMTS/XYZ 请求 |
| 核心引擎层 | .NET 10, SkiaSharp, ProjNET | 地图渲染管线，样式系统，坐标变换，OGC 协议逻辑 |
| 数据源层 | Npgsql, GDAL, SkiaSharp | 数据源抽象与实现，配置存储与加载 |

## 三、核心流程

### 3.1 WMS 请求处理流程（GetMap）

```
客户端 HTTP GET 请求
        │
        ▼
┌─────────────────────────────────┐
│  WMSController.GetAsync()       │
│  参数验证（request=GetMap,      │
│  layers, srs, bbox, width,     │
│  height 等必填参数）            │
└──────────┬──────────────────────┘
           │
           ▼
   ┌───────┴───────┐
   │ WmsCluster?   │
   └───────┬───────┘
        ┌──┴──┐
        │ 是  │ 否
        ▼     ▼
┌──────────────┐ ┌───────────────────┐
│ IWMSGrain    │ │ WmsService        │
│ .GetMapAsync │ │ .GetMapAsync()    │
│ (Orleans     │ │                   │
│ Stateless,   │ │ 1. 参数验证        │
│ 负载均衡)    │ │ 2. 图层查询(Store) │
└──────┬───────┘ │ 3. 权限校验        │
       │         │ 4. 创建Viewport    │
       │         │ 5. 计算Scale       │
       └────┬────┘ 6. 创建Map         │
            │    7. 渲染图片          │
            ▼                        │
   ┌─────────────────────────────┐   │
   │ Map.GetImageAsync()         │   │
   │ 1. 创建SkiaSharp上下文       │   │
   │ 2. 倒序遍历Layer列表          │   │
   │ 3. 每个Layer.RenderAsync()  │   │
   │    - 可见性判断               │   │
   │    - 坐标系转换               │   │
   │    - 范围相交判断              │   │
   │    - 矢量/栅格/瓦片分发       │   │
   │ 4. 输出PNG/JPEG图片          │   │
   └────────────┬────────────────┘   │
                │                    │
                ▼                    │
   ┌─────────────────────────────┐   │
   │ 返回图像流到HTTP响应         │   │
   └─────────────────────────────┘   │
```

### 3.2 WMS GetFeatureInfo 处理流程

```
客户端 HTTP GET 请求
        │
        ▼
WMSController.GetAsync(request=GetFeatureInfo)
        │
        ▼
WmsService.GetFeatureInfoAsync()
  1. 参数验证（layers, srs, bbox, width, height, x, y）
  2. 图层查询
  3. OGC 坐标转换
  4. pixel-to-coordinate 计算
  5. 10 像素 buffer 范围（pixel sensitivity）
  6. 遍历图层进行空间查询
  7. 收集 Features，限制 featureCount
  8. 返回 GeoJSON FeatureCollection
```

### 3.3 WMTS 请求处理流程

```
客户端 HTTP GET 请求
        │
        ▼
WMTSController.GetAsync()
  1. 计算缓存路径 (Utility.GetWmtsPath)
  2. ❓ 缓存命中? ──是──▶ 直接返回缓存文件
        │ 否
        ▼
  3. IWMTSGrain.GetTileAsync (StringKey, Grid路径)
        │
        ▼
WMTSGrain → WmtsService.GetTileAsync()
  1. GridSet 查找（tileMatrixSet）→ 获取瓦片范围
  2. 图层名解析（支持 resourceGroup:layer 格式）
  3. 图层查询（Store）
  4. 权限校验
  5. 创建 viewport（瓦片尺寸、范围、scale）
  6. Map 渲染（同WMS渲染管线）
  7. 保存到缓存文件
  8. 返回图片
```

### 3.4 XYZ 瓦片请求处理流程

```
客户端 GET /xyz/{layers}?x={x}&y={y}&z={z}
        │
        ▼
XyzController.GetAsync()
  1. 参数映射：z→tileMatrix, x→tileCol, y→tileRow
  2. 默认 tileMatrixSet = EPSG:3857
  3. 计算缓存路径，检查缓存
  4. 复用 IWMTSGrain 处理（stringKey 相同）
  5. 返回瓦片图像
```

### 3.5 集群与单机模式差异

| 特性 | 单机模式 (Standalone=true) | 集群模式 (Standalone=false) |
|------|---------------------------|----------------------------|
| Orleans 集群 | LocalhostClustering（内存） | ADO.NET 集群管理（PostgreSQL） |
| Reminder | InMemoryReminderService | ADO.NET ReminderService |
| 部署 | 单进程 co-host（Silo+Client） | 多节点独立部署 |
| WMS 路径 | 直接调用 WmsService | 通过 IWMSGrain 分发 |
| 端口 | 自动分配 | 需配置 SiloPort/GatewayPort |
| 适用场景 | 开发调试、单机小规模 | 生产环境高可用 |

## 四、Orleans Actor 模型设计

### 4.1 Grain 键类型设计

| Grain 类型 | 键类型 | 键值 | 设计理由 |
|------------|--------|------|----------|
| IWMSGrain | IntegerKey | 0 | 所有 WMS 请求使用同一个 IntegerKey，配合 [StatelessWorker] 在集群内自动负载均衡 |
| IWMTSGrain | StringKey | Grid 路径 | 同一 Grid 的所有瓦片路由到同一个 Silo，利用缓存局部性 |
| IXyzGrain | StringKey | 待定 | 暂未实现 |

### 4.2 WMSGrain 设计

```csharp
[Reentrant]
[StatelessWorker]
public class WmsGrain : Grain, IWMSGrain
```

- **Reentrant**：允许并发请求进入同一个 Grain，提高吞吐量
- **StatelessWorker**：Orleans 在每个 Silo 上维护多个副本，自动负载均衡
- **不维护状态**：每个请求独立处理，不保留状态

### 4.3 WMTSGrain 设计

```csharp
public class WMTSGrain : Grain, IWMTSGrain
```

- **StringKey**：键值为瓦片 Grid 路径（如 `wmts/polygon/EPSG4326/5/10/20.png`）
- **同 Grid 调度**：同一 Grid 的所有瓦片路由到同一 Silo，最大化缓存利用率
- **状态**：不持久化状态，使用默认内存存储

### 4.4 Grain 调用链路

```
API (ASP.NET) ──▶ ClusterClient.GetGrain<T>(key) ──▶ Grain 方法
                                  │
                     Orleans 集群路由 (Grain Placement)
                                  │
                     ┌────────────┴────────────┐
                     │  Same Silo (本地调用)     │
                     │  Different Silo (远程)   │
                     └─────────────────────────┘
```

## 六、配置架构

### 6.1 配置层次

```
环境变量 (ZSERVER_ 前缀)
        │ 覆盖
        ▼
配置文件 (conf/appsettings.json)
        │ 包含
        ▼
配置提供者 (config.provider)
        ├── file: 读取本地 JSON 文件 (conf/zserver.json)
        └── socodb: 从远程 API 获取配置
```

### 6.2 配置存储流程

```
启动时
    │
    ▼
ZServerBuilder → ServiceCollectionExtensions.AddZServer()
    │
    ├──▶ LayerStore.LoadAsync()
    │      从 JSON 反序列化
    │      写入 MemoryCache
    │
    ├──▶ SourceStore.LoadAsync()
    │      创建数据源实例 (反射)
    │      写入 MemoryCache
    │
    ├──▶ StyleGroupStore.LoadAsync()
    │      从 JSON 反序列化
    │      写入 MemoryCache
    │
    ├──▶ GridSetStore.LoadAsync()
    │      从 JSON/内置定义加载
    │      写入 MemoryCache
    │
    └──▶ SldStore.LoadAsync()
           SLD XML 解析
           写入 MemoryCache

运行时刷新
    RefreshConfigService
    定时/手动触发 Store.Refresh()
    重新加载配置到 MemoryCache
```
