ZServer

基于 Actor 模型的分布式计算地图服务器

符合 OpenGIS Web 服务器规范，支持 WMS / WMTS 协议，天然水平扩展

快速开始 GitHub
v1.5.4 · .NET 10 · Orleans 10

核心特性

ZServer 将地图瓦片模型与 Actor 模型天然结合，提供高性能、可水平扩展的地图服务

🌐

OGC 标准兼容

完整支持 WMS（GetMap / GetFeatureInfo）和 WMTS 协议，兼容主流 GIS 客户端（QGIS、Leaflet、OpenLayers）

⚡

Actor 模型

基于 Orleans 实现，每个瓦片对应一个 Actor，天然无锁并发。水平扩展只需添加 Silo 节点

🔌

多数据源

支持 PostgreSQL/PostGIS、ShapeFile、COG GeoTIFF、远程 WMTS 等数据源，可扩展插件式架构

🎨

SLD 样式

支持 SLD（Styled Layer Descriptor）样式配置，灵活控制地图渲染风格

📦

瓦片缓存

本地文件系统缓存 + 实时渲染，兼顾首次加载速度和重复访问性能

🛡

授权认证

内置 JWT 认证 + 基于 Scope 的授权策略，支持生产环境安全控制

系统架构

基于 Orleans 的分层架构，从数据接入到地图输出完整链路

HTTP ASP.NET Core · WMS / WMTS / XYZ 控制器 · JWT 认证
Grains WMSGrain · WMTSGrain · XyzGrain — 无状态工作者，[Reentrant] 并发
Server LayerStore · SourceStore · GridSetStore · StyleGroupStore
Rendering SkiaSharp · Style→Visitor→Renderer 管线 · 动态编译 (CQL 过滤)
Data Sources PostgreSQL / PostGIS · ShapeFile · COG GeoTIFF · GDAL

支持的数据源

插件式数据源架构，可轻松扩展

🐘

PostgreSQL / PostGIS

矢量数据存储，支持空间查询和过滤，生产环境首选

📐

ShapeFile

经典 GIS 矢量格式，快速加载本地数据

🛰

COG GeoTIFF

云优化 GeoTIFF，支持高效影像数据发布

🌍

GDAL

通过 GDAL 支持更多栅格和矢量格式

🔗

远程 WMTS

代理远程 WMTS 服务，统一接口管理

🧩

插件扩展

实现 IVectorSource / IRasterSource 接口即可添加新数据源

快速开始

3 步启动 ZServer

1

启动 PostgreSQL

docker run --name postgis \
  -p 5432:5432 \
  -e POSTGRES_PASSWORD=1qazZAQ! \
  -d postgis/postgis
2

启动 ZServer API

git clone https://github.com/zmaplab/zserver.git
cd zserver

dotnet run --project src/ZServer.API \
  --Standalone true \
  --ClusterDashboard true \
  --ClusterDashboardPort 8182 \
  --Port 8200
3

访问服务

# 浏览器打开
http://localhost:8200/wms?request=GetCapabilities

# 或使用仪表盘
http://localhost:8200/dashboard
